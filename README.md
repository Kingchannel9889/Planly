# Planly

An Android-first, local daily planner built with Expo SDK 57, React Native 0.86.3, TypeScript, and Expo Router. The blue/navy visual system follows the reference boards in `design/`. The account phase adds a FastAPI/PostgreSQL backend, email/password sign-in, and revision-checked planner synchronization. Automatic allocation, recurrence, and real AI remain outside this delivery.

## Run

### Fully local Android APK

The `local` EAS profile builds a standalone release APK with `EXPO_PUBLIC_LOCAL_ONLY=true`.
It opens directly into daily setup, stores its planner on the device, schedules local reminders,
and never signs in or calls the Planly API. No Metro, Docker, Wi-Fi, or hosted backend is needed
to use the installed app. Account build profiles keep their existing behavior.

```sh
npx eas-cli@latest build --platform android --profile local
```

Local data uses a separate storage namespace. Existing account planners are not deleted or
automatically adopted. Before changing editions, export your planner from Settings, then use
Import Backup in the local edition. Keep backups outside app storage before uninstalling,
clearing app data, or replacing your phone. The APK uses the existing Android package and
signing credentials so it can update the development app when signatures match.

For local-mode development in PowerShell: `$env:EXPO_PUBLIC_LOCAL_ONLY='true'` then
`npx expo start --dev-client --clear`. Remove that environment variable to return to account mode.

### Account edition

```sh
npm ci
# Configure .env using .env.example (see backend/README.md)
docker compose up -d --build
npx expo start
```

For the browser development preview, run `npm run web`. Browser storage is separate from Android storage, and native notifications are unavailable in the browser.

Use a development build for Android device testing. Native folders are generated by Expo; do not edit them manually.

```sh
npx eas-cli@latest login
npx eas-cli@latest build --platform android --profile development
npx expo start --dev-client
```

Install the APK from EAS, then connect it to Metro. `eas.json` also contains an installable preview APK profile. No cloud build, signing, or store submission has been performed. The default app identifier is `com.topp.planly`; change it before publishing if needed.

## Included

- Empty first launch with optional name, wake/sleep times, and evening review time.
- Today / Tasks / Tomorrow / Settings, plus task details and editing. Tomorrow opens next-day review directly from the bottom navigation.
- Flexible tasks, fixed appointments, manual date/time blocks, search, filters, duplicate, complete/reopen, one current task, and delete with Undo until leaving the deletion screen.
- Independent completion, planning, remaining-work estimates, deadline risk, occurrence acknowledgment, and notification history.
- Local persistence with serialized writes, surfaced storage failures, and no automatic overwrite of unreadable data.
- Validated JSON export/import. Imports replace the local planner only after confirmation; invalid files leave existing data intact. Backups include entries, settings, completion, and risk history, but never device notification identifiers.
- Start reminders, one-shot risk alerts, evening review, and wake-time summaries. Enable notification permission and save reminder preferences in Settings.

## Rules and boundaries

Overdue means an incomplete task's deadline has passed. Unfinished means its planned end has passed; both can apply independently. Critical is usable time <= remaining work + 30 minutes; Urgent is <= twice remaining work + 30 minutes. Otherwise high user priority is Important, and other tasks are Normal.

Usable time excludes the union of fixed appointments and local sleep intervals. Multiple gaps count; flexible blocks are not reserved time in this estimate. Suggested Next ranks Critical, Urgent, Overdue, Important, Normal, then smallest spare time, user priority, and earliest deadline. Future-planned tasks surface early only when risk is Urgent, Critical, or Overdue. Overdue work also has its own Today section.

Moving or unscheduling work never changes the deadline. Updating remaining work never resizes the planned block. Fixed appointments become Past rather than acquiring unfinished/completion prompts. Overlaps warn but can be saved intentionally.

Dates/times with instants retain their instant when travelling. Wake, sleep, and review clocks follow the phone's time zone. Day-only planning stays a calendar date. Deadline time starts at 11:59 PM. Tasks without deadlines use user priority.

## Notifications and data

The OS owns scheduled delivery while the app is closed; no background JavaScript or push server is required. The planner refreshes its predictions on changes, every minute while open, and on resume. Daily review/summary predictions cover 14 days, and the nearest 60 events are queued to respect platform limits. Reopen the app to refresh that window. Large task lists can fill the queue earlier.

Quiet-hour risk transitions are recorded as consumed and represented by the wake summary, rather than replaying stale individual warnings. Changing a deadline resets its risk history. A newly Critical task receives only a Critical alert, not simultaneous Urgent and Critical alerts. Updating an estimate does not reset consumed alerts. The scheduler retains alarms delayed by Android until the OS consumes them. Delivery is still subject to battery restrictions, notification permission, device shutdown/force-stop behavior, and OS timing; this is not an exact-alarm guarantee. Device/time-zone changes are reconciled when the app next opens.

Planner data is cached per account using unencrypted AsyncStorage and synchronized to PostgreSQL through FastAPI. Exported JSON is also unencrypted. Native session tokens use Expo SecureStore; browser sessions use server-managed HttpOnly cookies and survive refresh. Logging out preserves local planner data and stops reminders on that device. Keep manual backups somewhere you control. No AI service or analytics is connected.

## Code map

### Accounts, settings, and synchronization

See [backend setup](backend/README.md) for database commands, API configuration, and deployment boundaries.

Welcome supports registration and sign-in. Passwords require at least 6 characters, with no field-specific maximum, and are stored as Argon2 hashes on the server. Password fields include show/hide eye buttons. Seven-day opaque sessions are revocable and stored as hashes in PostgreSQL. Change Password revokes other sessions. This development delivery has no email verification or forgotten-password email flow.

Logging out requires a server connection to revoke the session, then removes only the secure credential and returns to Welcome. Planner caches and reminder history remain. Sign in to the same account to restore access. An unexpired cached session can use its local planner offline; the server rechecks authorization on every request. A revoked or expired session returns to sign-in when detected. Local caches are not encrypted and are not an OS-level security boundary.

Local edits are committed first; sync runs after edits, every minute while open, on resume, and from Settings. Failed network requests keep the local dirty copy for retry. The first download requires a connection if no account cache exists. PostgreSQL stores tasks, appointments, user settings and notification preferences in dedicated account-scoped tables, updated atomically with a versioned recovery snapshot. Migration `002` preserves existing planners. Atomic revision checks reject stale writes. Settings offers an explicit choice of device or server copy after a conflict, with export before replacement. There is no automatic merge or background cloud sync while closed.

Creating an item opens its saved details rather than returning silently to a filtered screen. Today, Tasks and task details show sync status and offer retry/conflict actions. A local save is distinguished from a successful account sync. Tasks has counted All, Today, Upcoming, Unscheduled and Completed views, with optional attention filters. The Today and Tasks add buttons open Quick Add; its More options action preserves the draft in the full editor. Today intentionally filters by date and attention rules; all saved items can be found under Tasks with the All filter.

Existing pre-account data at `planly:data:1` is preserved. After sign-in, **Settings → Import previous local planner** previews a replacement confirmation. It is never silently assigned to a new account. JSON import/export cannot change the authenticated identity, token, or sign-in email.

Profile names and planning preferences synchronize. Account email is read-only. Notification preferences remain separate switches; reminders are scheduled locally only for the active account, with account-specific history. The UI label Normal maps to the model's Medium priority. Important remains red.

Manual account checks: register, add a task, restart, log out, sign in again, and confirm the task remains; sign in to a second account and confirm isolation; edit offline and reconnect; create conflicting edits on two devices and check both resolution choices; change password and verify the old session is rejected. Rebuild the native development client after adding SecureStore.

### Modules

- `src/app`: route screens only, protected onboarding, and four-tab navigation.
- `src/components/planner`: reusable UI, native date/time controls, and task cards.
- `src/core`: platform-independent models, attention rules, interval union, reminder predictions, and backup validation.
- `src/store`: single local source of truth and serialized durable mutations.
- `src/services`: notification and backup adapters, with explicit browser fallbacks.
- `tests`: rule and notification-adapter regression tests, using Node's test runner and in-memory TypeScript compilation.

The original starter's unused visual components remain outside the route tree. FastAPI/PostgreSQL is connected through the service/store boundary. Future AI adapters can use the same domain model.

## Verification

```sh
npm test
npx expo lint
npx tsc --noEmit
npx expo install --check
npx expo export --platform web
npx expo export --platform android --output-dir dist-android
```

If Expo's Windows route watcher emits stale `../` route types after adding files, restart Metro before typechecking. Do not hand-edit `.expo/types/router.d.ts`.

Before relying on reminders daily, test a development APK on a physical Android device:

1. Complete setup; confirm the empty state. Add/edit tasks and an appointment, restart the app, and verify persistence.
2. Verify overlapping appointment/sleep intervals, deadlines crossing midnight, Critical/Urgent thresholds, and independent Unfinished/Overdue labels.
3. Complete/reopen, switch current task, postpone, unschedule, duplicate, and delete/undo. Confirm deadlines and estimates remain unchanged by planning actions.
4. Allow then deny notifications; schedule a near-term start reminder, close the app, and verify delivery/tap navigation. Test quiet hours, wake summary, deadline edits, and completion cancellation.
5. Export a backup, make a change, import and confirm replacement, then try malformed JSON and duplicate IDs. Existing data must survive failed validation.
6. Check small screens, large Android font sizes, keyboard access, TalkBack labels, time-zone changes, and tomorrow review.

Automated tests and JavaScript bundle exports do not substitute for physical-device notification or visual testing.
